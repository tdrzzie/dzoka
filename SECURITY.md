# Security

Dzoka has no released application or supported production deployment yet. Do not use the research workspace to store real lost-property, identity or verification data.

Report vulnerabilities privately using the repository host's private vulnerability reporting facility if enabled. If unavailable, request a private contact from the maintainers without publishing exploit details or sensitive data. A dedicated contact and response SLA must be established before any production release.

Include affected revision, reproduction steps using synthetic data, impact and suggested remediation. Do not include credentials, personal information or private ownership answers. Do not test against third-party or institutional systems without authorization.

Tenant isolation, release authorization bypasses, claim-answer disclosure, replay attacks and unsafe media processing are security-critical issues. Production readiness requires threat modeling, abuse tests, dependency and container scanning, credential response procedures and independently reviewed authorization boundaries.
