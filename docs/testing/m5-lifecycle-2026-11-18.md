# M5 indexing, projection reconciliation and durable history

The deployment DDL creates a concurrently built 384-dimensional cosine HNSW index over authoritative fingerprint components. Inserts and deletes are maintained transactionally by PostgreSQL. The application’s opt-in `pgvector-indexed` route validates index readiness, applies tenant, report, active rollout and exact model-space bounds, and retrieves a bounded shortlist. An HTTP test loads more than 512 visible opposite-kind reports and still returns the authorized vector and verified identifier match. Lexical and spatial/time routes flag that capacity limit. The first overflow test returned 503 before reaching the indexed path. The corrected implementation checks capacity before loading candidate evidence and the repeat passes.

Seven filtered synthetic queries over 1,200 vectors exercise HNSW with an independently executed exact baseline. Across tenant and query selections at K=1, 5 and 10, the index returns all 51 expected neighbors with no scope violations. These results do not establish representative Recall@K or a production service objective. [Filtered recall receipt](artifacts/m5-lifecycle-20261118/filtered-recall.json).

Qdrant’s private reconciliation API reads the active PostgreSQL projection, upserts immutable component IDs, then deletes stale points only within the assigned tenant and space. Two real reconciliations on the pinned service pass. The test confirms stale deletion, another tenant’s point surviving, permission checks, and route failure before provisioning. The private maintenance runner provides bounded scheduling entry points for reconciliation and expiry pruning, including tests for wrong origins, duplicate assignments and partial failure. A scheduler and its credential lifecycle still need configuring on the target host.

Durable history atomically stores run metadata and per-candidate evidence. Tests verify replay, changed-input conflict, actor and tenant isolation, denial after candidate deletion, bounded expiry pruning, and valid history retained through database restore. Payloads carry opaque references and evidence only. Source and candidate revision erasures cascade to the relevant records.

The calibration fixture has 200 disjoint fit and 200 supported holdout rows, with five sparse exclusions in each split. Holdout Brier is **0.174** against **0.200** for raw similarity on identical rows. The fixture uses authored fixed label frequencies. Live confidence stays `UNCALIBRATED`. Representative independent labels, thresholds and an approved runtime calibration artifact are outstanding. [Calibration receipt](artifacts/m5-lifecycle-20261118/calibration-holdout.json) and [fixture](artifacts/m5-lifecycle-20261118/calibration-fixture.py).

The source audit and architecture checks, all **240 Python tests**, **26 Java unit tests** and **79 core/media integrations** pass. The broad restore matches **38 tables and 2,031 rows**, with row/catalog equality, runtime-role tenant isolation and independent snapshots. Separate 15-case indexed/PostgreSQL and Qdrant/PostgreSQL suites each pass and restore a live recorded search and candidate. Their restores cover 38 tables with 1,198 and 172 synthetic rows respectively. All runs reported zero failures or skips on the final source. These are local conformance suites; the separate full M4 gate is not repeated for this slice.
