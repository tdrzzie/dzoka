# Executed CPU diagnostic source artifacts

These are exact first-party driver/Dockerfile bytes used by the November 16 local model comparisons. `manifest.json` binds each driver/build pair, immutable local image and reviewed runtime closure. They are an evidence archive, not registered production providers or a claim of broker/core integration. Driver code is independently authored under the repository MIT license. The Dockerfiles expect the offline build context described below; they cannot download source, packages or models.

The context contains the pinned llama.cpp source tree and existing digest-locked Debian packages from `ai/shona-cpu-build.lock.json`, plus the reviewed notices and one selected driver renamed `afri-driver.cc`. `minimal-runtime-debs` contains only reviewed libc6/libc-bin archives. The exact library source/pins/build flags and other runtime obligations are in the linked closures under `docs/dependencies/notices/afrislm-20261116/` and `morena-20261116/`. The complete downloaded archive and all selected regular source files were independently checked against their upstream identities before build.

Models are external verified assets mounted read-only at `/model/model.gguf`; do not embed them in these images. The separate few-shot variant additionally requires its exact private context asset at `/model/examples.bin`. Images have no model download mechanism. Their binary protocol accepts two little-endian u32 values (fixed direction and bounded source byte count), exact UTF-8 source bytes and EOF; replies contain six little-endian u32 fields (magic, raw-source token count, prepared-prompt token count, output token count, EOS flag, text byte count), followed by UTF-8 output. All text is unverified evidence. Generated counts include the EOS token when present; raw-source counts exclude prompt/control/BOS additions. Oversize or malformed input fails rather than silently truncating it.

Actual model/configuration hashes, constrained container readback, private receipt hashes, source/reference matching, coverage, quality failures and limitations belong to the [execution record](../../m4-african-cpu-quality-2026-11-16.md). No upstream test suite, native-speaker approval, institutional sign-off, portable deployment or unrestricted translation quality is claimed by this archive.

The evaluator and framing-test snapshots are the exact first-party scripts executed from the local `.test-tmp` staging area, as bound by `evaluator-manifest.json` and the private plans. They expect the documented ignored caches, temporary build records, repository tools and immutable per-user attempt names. They deliberately refuse overwriting existing attempts. The zero-shot MORENA wrapper reads the archived AfriSLM evaluator under its original staging name. This archive supports inspection of the actual executed logic; it is not a general-purpose CLI or an assertion that those private/local prerequisites are supplied with a clone. Corpus files, generated translations, credentials and model binaries are excluded; the inline eight synthetic pairs are independently authored test material.
