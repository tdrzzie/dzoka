## Reference and human-review protocol

Before a quality run, retain a private record identifying dataset owner, permission/license basis, allowed uses, retention/hold rules, item/entity/institution/time groups, split construction and reviewer access. Document reference provenance and projection geometry/class vocabulary. Compare a pinned baseline and candidate on the same held-out cases, retain unavailable/truncated/unknown-input coverage and report slices individually. Select task-specific tolerances before inspecting candidate test results. No default threshold in this repository is an achieved or institutionally approved accuracy requirement.

For structured attributes, reviewers check each proposal against exact source evidence, distinguish absent information from contradiction, and record unsupported/misbound spans. For translation and code-switching, qualified speakers assess preserved meaning, person/number/negation, names, temporal/location uncertainty, protected spans and omission/invention; exact/WER/CER alone cannot approve semantic quality. For English drafts, reviewers assess each factual assertion against the source report and mark invented attributes, unsupported certainty, omitted uncertainty, unsafe guidance and whether the output stayed within the requested task. Record reviewer disagreement/adjudication rather than treating one generated output as its own reference.

For embeddings/local features, use independently labeled same-item/different-item and hard-negative pairs across capture conditions, institutions and time. Cosine is an observed measure, never a calibrated probability or ownership decision. For detection/segmentation, independently annotate geometry/classes using a documented projection; preserve small/occluded/background/missing-input slices and duplicate predictions. Box greedy-count and mask-overlap protocols are scoped diagnostics, not a replacement for any specifically required AP, instance-segmentation or retrieval benchmark. For reranking, independently label relevance on a declared candidate set and retain candidate coverage; returned-list metrics cannot establish corpus retrieval recall.

Keep raw references, reviewer identities, decisions and source outputs in authorized private stores. The public/repository record may retain permission-safe hashes, counts, scope and acceptance disposition. A hash alone does not certify permission, independent labels or accuracy. Final sign-off must name evaluated profiles/versions, dataset/split/projection/result identities, requirements, slices, failures and accountable approval. No synthetic fixture or passing local gate supplies that sign-off automatically.

## Verification and deployment release barrier

Run the full local gate with explicit pinned private model and management releases, all native providers, service/core integration and restore. A missing, failed or skipped required phase blocks whole-suite acceptance. Preserve historical failed runs. After any source fix, rerun against its new source identity; compilation alone is insufficient. Remote CI results remain separate from local evidence.

Deployment requires the chosen operator to provision least-privilege identity, secret/IdP lifecycle and protected configuration/state; install the service; apply reviewed broker/core/daemon network policy; then execute target-host startup/stop/restart/boot and failure recovery. Local foreground verification does not prove installed-service behavior. Provisioning defaults or guessing an institutional identity/retention/SLO policy cannot replace operator approval.

M4 stays open while these required acceptance inputs or results are absent. Future product/HA/index work remains tracked under its own milestone; external prerequisites do not excuse implementable local gaps.
