# 0058. Federation wire protocol and EPCIS projection

- Date: 2026-11-26
- Status: Accepted for implementation under ADRs 0017 and 0019–0021

One deployed federation identity serves one configured tenant. Tenant administrators register peers and append or revoke Ed25519 verification keys. Trust is bilateral, explicit and confined to search and capability discovery. Deployment configuration separately permits the outbound HTTPS origin for each peer. Origin and TLS verification, redirects, timeouts and byte limits apply before handling a response. Loopback HTTP is available only in fixtures.

Version 1 signs an ASCII preamble followed by the version, operation, issuer, audience, key ID, canonical request UUID, issued and expiry epoch seconds, and lowercase SHA-256 of the decoded payload, each separated by a single LF. JSON property order and encoding outside the decoded payload are independent of the signature. Ed25519 keys use the existing JCA implementation. Responses bind the same request ID and reverse issuer and audience. Signed capability responses enumerate the supported wire versions and operations. Reject unknown fields, unsupported versions and unsigned or expired exchanges. Persist authenticated nonces and outcome metadata with per-peer time windows. Fan-out returns separately attributed peer statuses and interleaves ranks. The payload contains neither raw scores nor an aggregate probability. [Ed25519 specification](https://www.rfc-editor.org/rfc/rfc8032.html).

Discovery is limited to explicitly published, current found-report revisions. The projection uses a fixed category enum, country code and calendar month. Results contain opaque offer references, local rank, freshness at month resolution and a fixed policy/algorithm identifier. It has no free-text, contact, private ownership evidence, coordinates, vectors or globally comparable confidence. Remote discoveries carry no authority to mutate local custody.

Use EPCIS and CBV 2.0.0 JSON-LD `ObjectEvent` with `OBSERVE` for three native facts, recorded storage, accepted staff transfer and recorded owner return. Export an independently allocated object URI and capture event URI, with UTC timestamps and no actors, precise sites, verification material or raw native identifiers. Mapping 1 records observations without a business step. Mapping 2 adds the applicable CBV storing or receiving step. The owner return retains the observation without asserting a CBV business step. An explicit correction appends a new event and an error declaration that preserves the original fields and references the corrective event. The native event remains unchanged. Local workers project and submit independently of custody writes. External `202 Accepted` is a submission receipt, with successful capture confirmed through the fixed repository's job endpoint. Uncertain submissions require reconciliation before further sends. [GS1 EPCIS 2.0.0](https://ref.gs1.org/standards/epcis/2.0.0/), [GS1 artefacts](https://ref.gs1.org/standards/epcis/2.0.0/artefacts).
