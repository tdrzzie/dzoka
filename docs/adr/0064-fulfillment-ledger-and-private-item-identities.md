# 0064. Fulfillment operations, reward ledger and private item references

- Date: 2026-11-26
- Status: Accepted for the local fulfillment profile

Implement M10 in separate logistics, rewards and passport modules using existing Java, PostgreSQL, JWT and HTTP dependencies. No new dependency, provider SDK, blockchain or downloaded code is required. Introduce replaceable CourierProvider, PaymentProvider, RewardEscrowProvider and ItemIdentityProvider contracts. The optional HTTP fulfillment gateway uses an explicitly versioned Dzoka contract; it is not represented as a vendor API. With no gateway configured, dispatch fails closed. Local tests run a real loopback HTTP sandbox only with explicit test configuration.

Persist provider intent and stable tenant-scoped keys before network calls. A leased dispatcher records an attempted send before leaving its transaction. Reclaimed sends and ambiguous responses reconcile before any resend. Only a confirmed NOT_FOUND result under the gateway idempotency contract permits resending the identical operation. Callbacks are authenticated, time-bound, input-hashed and replay checked. Provider facts never grant release authority.

Courier requests require claimant address consent expressed as an opaque provider-vault delivery reference. Staff authorization, current recovery review, report state, holds and custody are rechecked at booking and physical dispatch. Record courier possession separately from owner return. Delivery alone cannot confirm ownership or settle a reward. A claimant confirmation after dispatched/delivered evidence can record owner receipt under the dispatch authorization; revocation, changed policy, report unavailability and holds stop that step. Custody mutations retain append-only evidence.

Rewards are optional. Terms fix payer, beneficiary, currency, integer minor units, fee and policy evidence. Each immutable ledger transfer represents equal debit and credit entries exposed through a security-invoker ledger view. Serializing reward operations and unique logical transfer keys prevents duplicate settlement. External reservation and confirmed settlement remain distinct. Disputes freeze release/refund until independent review. No reward state participates in property-release authorization.

Registered items are actor-private opaque records. Random revocable QR/NFC tokens resolve only to a generic finder-contact capability. Authenticated, rate-limited, phrase-only relay avoids exporting phone numbers, addresses or arbitrary private text. Registration, tag possession and passport references never create recovery claims or ownership evidence. Private external identity assertions retain provider/version/evidence provenance. DID and blockchain verification require separately adopted adapters and remain unavailable by default.

Persist early tracking facts and project them after authorized handoff. Source observation time orders terminal delivery/loss/return facts; intermediate updates cannot downgrade delivery. A shipment returned to staff restores institutional custody and makes its approved claim pending for renewed verification. It does not confirm owner recovery. A cleared hold or policy change invalidates the original receipt snapshot; a reviewer with both recovery and logistics authority, independent of the claimant and original custodian, can append a current receipt authorization. It never changes the original dispatch evidence.

Post-settlement disputes can queue a separately authorized reversal. Only a gateway confirmation that payout and fee were recovered and refunded posts compensating beneficiary/fee-to-payer transfers. Rejection or uncertainty never fabricates recovered funds. Conflicting terminal payment callbacks open a dispute and retain their evidence.

The executable loopback development provider uses the existing CPython standard library and bundled SQLite, with no installation or Core dependency change. [Python licensing](https://docs.python.org/3.14/license.html) covers its standard-library runtime; [SQLite's publisher](https://www.sqlite.org/copyright.html) dedicates its deliverable implementation to the public domain. No upstream source or runtime binary is redistributed by this change. The SQLite state represents synthetic effects only. It is not a production courier or payment rail.
