# 0053. Bounded matching over active fingerprint snapshots

- Status: Accepted and implemented for local conformance
- Date: 2026-11-18

The mandatory audit gate and the [matching baseline](../architecture/matching-architecture.md) govern this slice. Reuse the authoritative report revision, tenant memberships and active fingerprint rollout. Keep retrieval rank, evidence similarity, coverage, confidence and ownership as separate values. No existing provider or M4 quality decision changes.

Add a private matching endpoint requiring both `matches:read` and `reports:read`. Search an opposite-kind pool visible to the user as owner or through `reports:read:any`. Exclude expired and deleted reports. Statement scope plus row-level policies protect the report, revision and active model space reads. Use the caller-selected exact compatible space and the tenant's active rollout. Ignore shadow, stale, disabled, dimension-mismatched or truncated components. Return opaque candidate and component references, route ranks and score metadata. Do not expose report text, locations, vectors or protected identifier digests.

A trusted verifier can append a manufacturer-scoped serial attestation with `matches:attest-identifiers` and independent report access. A tenant-bound verified issuer is responsible for generating keyed digests and determining comparability. The core accepts no raw identifier, never echoes a digest and compares only attestations in the same scope and key version. Mapping and issuer trust are operator obligations. A hard contradiction takes precedence in disposition and ranking. OCR or unverified text never produces an identifier attestation. Revision erasure cascades to the protected attestation.

The bounded pool is at most 512 candidates. Crossing the bound produces explicit capacity status and no arbitrary sample. Each identifier, lexical, spatial/time and exact-vector route returns at most 20 rows. Reciprocal rank fusion preserves route ranks. Deterministic evidence reranking examines up to 20 fused candidates and reports output truncation. Description-derived signals share one reliability budget. Location uncertainty reduces context reliability and unknown intervals stay unavailable. No comparable evidence means no similarity value. Missing evidence does not lower similarity or grant confidence. All results are uncalibrated.

Local backends are JDK exact cosine, the reviewed pgvector operator over the same authorized bounded snapshot, and a same-host Qdrant exact query with tenant, space and active component allowlist filters. Query scores determine vector rank. Scoring uses authoritative vectors. Unavailable or incomplete backends explicitly fail the route and preserve other results. Qdrant requires an approved projection of immutable active components. Its synthetic conformance fixture provisions that projection and inserts a stale point to validate rejection. The integration does not claim a production automatic projection lifecycle. The separate HNSW test uses synthetic authoritative vectors and compares measured filtered Recall@10 against a known exact query. Production pgvector remains the design default, subject to an approved live index design and adoption review.

The [pgvector](../dependencies/m5-pgvector-diagnostic.md) and [Qdrant](../dependencies/m5-qdrant-diagnostic.md) artifact decisions authorize disposable local tests. No JVM dependency or shared service changes. Alternatives include silently truncating the tenant corpus, comparing embeddings by dimension alone, and using aggregate similarity as an ownership decision. Those alternatives violate repository invariants. Large-scale index projection/reconciliation, durable search evidence, trained reranking and calibration approval remain tracked in the acceptance record.
