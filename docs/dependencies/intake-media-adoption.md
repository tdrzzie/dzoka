# Intake and private-image adoption

Review date: 2026-10-26. Scope: M3 report intake, private S3 object operations and sandboxed PNG/JPEG canonicalization. This does not approve arbitrary document/video/audio decoders, a production storage distribution, or antivirus certification.

Approve AWS SDK for Java S3 and URLConnection HTTP client **2.56.0** under Apache-2.0, with inherited SDK modules recorded in the updated artifact lock. Exact S3 POM and versioned LICENSE/NOTICE were inspected at [2.56.0](https://github.com/aws/aws-sdk-java-v2/tree/2.56.0). Use only explicit credentials, region and endpoint; disable unused Apache/Netty transports and do not discover credentials from metadata servers. Preserve AWS/embedded third-party notices. SDK request/checksum behavior is described in [AWS checksum documentation](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/s3-checksums.html); independently verify bounded object length and SHA-256 against the database manifest. Public URLs/ACLs are never issued by the application. Dependency POM license declarations and exact JAR digests must pass the existing lock gate after resolution.

Reactive Streams `1.0.4` is a transitive SDK API dependency under MIT-0 (exact POM and versioned LICENSE reviewed); admit that grant explicitly rather than bypassing the lock's unknown-license failure. Other resolved new SDK modules use the recorded Apache-2.0 declarations. This bounded review does not certify every transitive source path.

Approve SeaweedFS **4.51**, source commit `153ab668c99731a6d29492bf6c61d0b4fa701101`, as an external disposable S3 integration-test server. Its root LICENSE is Apache-2.0. Inspected `weed/s3api/s3api_auth.go` authentication classification, `s3api_server.go` IAM configuration/enforcement (including the allow-all risk when no identities are configured), and `s3api_object_handlers_put.go` put/size/versioning/metadata behavior. Tests must configure explicit random access credentials, verify anonymous denial, publish only the S3 loopback port, and mount no user data. The approved Linux amd64 image manifest is `chrislusf/seaweedfs@sha256:3a522c379599e163433a636e75022630848b63a74f08ea37bf06f8d776e9a707`. This is an integration compatibility reference, not a production server recommendation or complete source/security audit. Production can use a separately reviewed private S3 service; no MinIO server is installed or bundled.

The same release's Windows amd64 test-server archive is approved for isolated native verification when Docker is unavailable: `https://github.com/seaweedfs/seaweedfs/releases/download/4.51/windows_amd64.zip`, GitHub release asset SHA-256 `08866a53e1bdd5378ee9880f8ee30d981d1bbb6ae22ee1897deb17ff87f8d2fb`. Verify before extraction/execution. The `mini.go` binding/config/port flags were inspected; bind all native listeners to loopback and use a fresh test directory. This does not enable a native production-decoder fallback.

The raster sanitizer uses standard JDK ImageIO, already covered by JDK adoption, in a separate network-disabled Docker process. The approved Java 21 JRE image is pinned in the runtime manifest/configuration; its Temurin Dockerfile at `adoptium/containers` commit `511f9356dc4d50932a0a5f8cfb0f87ed1aef4f07`, `21/jre/ubuntu/noble/Dockerfile`, was inspected for Ubuntu base packages, exact `21.0.12.1+1` runtime, archive checksum/signature verification and entrypoint. Dockerfile is Apache-2.0; JRE libraries retain GPLv2/Classpath Exception and separate component notices. This external sandbox runtime is not source incorporated into the MIT core. Review/update images and advisories before production; the JRE OCI release differs from the host build JDK and CI JDK.

Sandbox requirements: non-root user, no network, read-only root and code/input mounts, disposable output/temp directories, memory/CPU/PID/time/output limits, no credentials or Docker socket inside the child. The core API never invokes a decoder or needs a Docker socket. A separately operated trusted core worker leases media tasks and invokes the sandbox. Canonical output copies decoded pixels into a fresh PNG and retains no source metadata. Strictly bounded PNG/JPEG only; SVG, archives, PDF, audio and video remain unsupported. Failure/unavailability is explicit and never activates source bytes for preview/AI. This is format isolation and canonicalization, not a generic malware-scan guarantee; additional scanner/content-provider adoption remains required for broader formats/production policy.
