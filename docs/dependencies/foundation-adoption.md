The parent POM digest is `b7310a4672ba54ba552cc74e6f62137890f361c93be04aa56def10a27552f9f5`; the Boot BOM digest is `3ebfa36de39b9231236456542b09daa0d071b6f4780209323dbe6795a4522124`. Versioned descriptors pin Spring Framework 7.0.10, Security 7.1.2, HikariCP 7.0.2, Jackson 3.1.7, Tomcat 11.0.27 and the driver/migration versions above. Runtime transitive artifacts must be inventoried with SHA-256 and declared licenses in `dependencies.lock.json` before declaring the build verified. Preserve embedded licenses/notices and include the inventory when distributing binaries; the MIT project license does not replace their grants.

Transitive families admitted for this scope: Spring/Apache Tomcat/Jackson/Hikari/Nimbus/Micrometer/SnakeYAML/Apache Commons/Log4j APIs under Apache-2.0, SLF4J under MIT, Logback under its EPL alternative, Checker annotations under their declared grant. JUnit/OpenTest4J/API Guardian are test-only. Unrecognized/missing terms require review rather than silent inclusion. Exact resolved POM license metadata and embedded notice evidence are retained with artifact hashes; this is a bounded adoption review, not a full transitive source audit.

Security review consulted [Spring advisories](https://spring.io/security/) including [CVE-2026-41707](https://spring.io/security/cve-2026-41707/), [CVE-2026-47841](https://spring.io/security/cve-2026-47841/) and [CVE-2026-47877](https://spring.io/security/cve-2026-47877/): their listed 7.1 fixes precede selected 7.1.2. This is not a claim that every dependency has no vulnerability. An automated advisory inventory remains required before production; new versions need renewed review and lock updates.

Compatibility/security decisions: stateless bearer-only API; no cookies/form login; no password storage; a reviewed external IdP supplies tokens. Required issuer/JWK endpoint/audience configuration is absent by default and startup fails. Local issuer/JWK HTTP is allowed only through an explicit integration-test flag. Local membership controls permissions and activation. Transaction-local tenant/actor settings reinforce RLS but are not a security boundary against an attacker holding arbitrary SQL execution as the application role; keep SQL parameterized and credentials private.

Migration/admin roles can alter schema/policies and remain operationally privileged. No app startup uses those credentials. PostgreSQL extensions, a live IdP product, Kafka publisher adapter, model artifacts and operational packaging remain deferred to the milestone that adopts them; generic product names are not installation approval.
