# Private structured attributes, translation and reranking

The [ADR 0031](../adr/0031-private-language-inference.md) profiles extend durable private perception jobs. [Adoption](../dependencies/language-adoption.md) records selected Apache-2.0 QA, OPUS-MT and official cross-encoder weights, exact immutable revisions and a rejected FLAN experiment. No new library, publisher project execution, runtime download or silent model fallback is used. Existing model/profile identities stay unchanged.

On the reviewed Windows amd64 CPU environment, `python tools/language_runtime.py fetch` explicitly downloads only the thirteen locked application artifacts into ignored `.audit-cache/language-models`. `check` verifies their exact byte counts/hashes and all runtime/source identities. `probe` executes authored synthetic fixtures through the actual local graphs. A licensed/executable model can still be unsuitable: the review records FLAN's failed time/translation examples rather than adopting it as the application backend.

Generate a disabled profile INSERT with `python tools/language_profile.py --tenant UUID --profile UUID --task ATTRIBUTES` (or TRANSLATION/RERANK). An authorized operator reviews/enables profiles separately. The key binds model/export/tokenizer/configuration, fixed questions, decoding/shape filters, runtime and provider source. Downloading never enables a profile.

For ATTRIBUTES/TRANSLATION, enqueue `POST /api/v1/tenants/{tenant}/reports/{report}/perception/text` with `{"profileId":"UUID"}`. Source is the current stored normalized report revision; original raw report text/request is retained independently. ATTRIBUTES requires an English language hint; TRANSLATION requires French and has an explicit English target. Regional `en-*`/`fr-*` hints are accepted. Unsupported hints fail before queue/storage reservation; no automatic language detection or identity translation is substituted.

ATTRIBUTES asks five fixed questions for category, brand, colour, location and time using the extractive QA graph, at most 256 paired tokens and sixteen answer tokens. Context-only start/end logits must beat the model's null-answer logit sum; that uncalibrated comparison is not confidence. Results contain per-field AVAILABLE/UNAVAILABLE, exact unique source quotation and UTF-16 `[start,end)` offsets, plus token/truncation metadata. Basic colour vocabulary, temporal-shape and source location-anchor checks can **reject** invalid proposals; they never scan/fill replacement facts. Field assignment remains a source-grounded proposal requiring appropriate confirmation. No generated serial/secret verification answers, normalized taxonomy, geocoding or inferred timestamp is created. Nearby time qualifiers remain in the quote and time uncertainty is explicitly UNINTERPRETED. Model spans are capped at sixteen tokens; attached qualifiers stay within the 128-character quote bound. Uncertain phrases remain quoted phrases.

TRANSLATION runs the dedicated Marian encoder/merged decoder with bounded full-prefix greedy decoding, cache branch disabled, PAD suppressed, 256 source tokens and at most 64 output tokens. It appends text, source/target languages and explicit input/output truncation. It never overwrites original text/language, feeds translations into ownership policy, or claims broader multilingual/production accuracy.

For RERANK, enqueue `POST .../reports/{report}/perception/rerank` with an exact JSON request of at most 16 KiB:

```json
{"profileId":"UUID","candidates":[{"id":"UUID","text":"caller-supplied candidate description"}]}
```

Supply one to eight distinct UUID client labels and nonblank candidate strings up to 512 Unicode characters each. The IDs are **opaque client labels**, never permission to fetch another report. Duplicate JSON keys, invalid Unicode, unknown fields, duplicate labels, unsupported input/profile and oversized/chunked bodies are rejected. The core binds the current normalized query and exact candidate strings into a digest-checked UTF-8 worker payload (at most 64 KiB), while preserving exact raw request bytes privately. Natural input/profile/query-revision idempotency returns the original job/request; candidate order is part of input identity.

Reranking runs the English official MS MARCO cross-encoder once per pair with a 512-token bound. Output contains each label exactly once, descending finite **raw logits**, stable label tie breaks and per-pair truncation/token counts. These are relevance scores, not probabilities, comparable cross-model scores, identity contradictions, ownership verification or release decisions. Read the exact authorized job through `GET .../perception/jobs/{id}/result`. Result access requires the report owner's/read authority; inference tokens cannot read ordinary results. M5 retrieval must separately construct authorized candidates, enforce hard contradictions and fuse evidence.

Configure `DZOKA_AI_CORE_URL`, scoped `DZOKA_AI_TOKEN`, `DZOKA_AI_TENANT`, `DZOKA_AI_PROFILE`, `DZOKA_AI_LANGUAGE_DIR` and the explicit development loopback exception if needed, then run `python tools/language_worker.py --once`. The launcher scrubs unrelated credentials, uses isolated Python and a 110-second process deadline; the durable lease is 120 seconds with existing retry/deadline policy. Only a live same-actor/tenant/profile/current-revision lease exposes binary input. No worker receives DB/S3 credentials or public storage URLs. Native deployment CPU/memory/filesystem/egress enforcement remains separate operational work.

All tasks share 32 pending AI jobs per tenant and 64 noncancelled perception jobs per report. Rerank raw requests **plus** exact worker payloads share the existing 32 MiB retained-input accounting with WAV bytes (the compatibility table remains named `perception_audio_usage`). Holds prevent erasure; eligible purge deletes both new raw/input data and components, cancels jobs and releases actual storage/reservations once. Raw text/requests never appear in status, events or worker failure messages.

ATTRIBUTES/TRANSLATION begin SHADOW and require explicit component pins, sealing and authorized activation to join fingerprints; separate coverage keys are `attributes` and `translation`. RERANK is always query-dependent: rollout validation, selected-provider filtering and the fingerprint domain reject it as an intrinsic component.

`python tools/test_intake.py --with-ai --with-perception --with-vision --with-language --restore-drill` runs all real local providers; `python tools/verify_local.py` requires all ten phases and their artifacts. Portable suites exercise lifecycle/security/geometry/grounding contracts and explicitly omit native inference. Representative datasets, broader languages/attributes/general LLM behavior, calibration, server-side retrieval/indexing, deployment isolation and production acceptance remain distinct requirements.
